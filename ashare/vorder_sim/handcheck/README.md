# 端到端人工核对(handcheck)

**手写 Flow 记录 + 手写虚拟订单 → 人工逐步推演出预期 → 跑程序对答案。**

```bash
./handcheck/run.sh
```

## 为什么需要这一层

`vsim_test.cpp` 用的是**内存里合成的 `UnifiedRecord`**,绕过了一整段真实链路:
CSV 解析、列名映射、**订单号取模 `norm()`**(Flow 的 `bidId` 带 channel 前缀 `2011000000000101` → `101`)、
时间戳解析、`instrumentID → market|symbol` 归一。这一层是唯一穿过它们的验证。

更重要的是:`expected.csv` 里的数字是**先人工推演出来的**,不是把程序输出抄下来当预期
(那样只能锁住行为,证明不了正确性)。十一个案例逐字段核对(198 字段);
这层先后抓出 **8 个真 bug**:终止腿 ahead 被继续扣减(case3)、OPT/PESS 缓冲毁掉竞价
uncross(case8)、竞价位移不入账(case8)、竞价边际公式在对手过剩簿上低估成交(case9)、
**收盘 uncross 后 15:00 打印经预算路径双吃同一批流动性**(case10)、竞价部分成交状态
误报 RESTING(case10)、**竞价打印对竞价腿队列双扣**(case11)、**转连续 reset 丢弃
排队位置**(case11;后两个由全市场画像选出的一字跌停股 000566 暴露)。

用 **SZ**(`isSH=false`)→ 无 resequence、无派生单,严格按 `seqNo` 处理,人工可精确推演。

## 案例 1:同价串行 + 异价饿死 + 位移

盘口:买 `10.00×500(#101)` `9.99×300(#102)` `9.98×200(#103)`;卖 `10.05×1000`
主动卖单 `#301` 限价 9.98,**Q=1500**;磁带逐档吃 500+300+200 = 1000(**slack=500**)

虚拟腿(t0=09:35):`va` 买@10.00×400 | `vb` 买@10.00×400 | `vc` 买@9.99×300

10.00 档队列:`[#101:500][va:400][vb:400]` (va 先挂 → 排 vb 前)

| 事件 | 动作 | 预算 b | 位移 |
|---|---|---|---|
| — | 起始 Q=1500 | 1500 | 0 |
| T1 500@10.00 | 吃 #101 的 500 | 1000 | 0 |
| | **va 吃满 400** | 600 | 0 |
| | **vb 吃满 400** | **200** | 0 |
| T2 300@9.99 | #102 要 300,只剩 200 | **−100** | **+100** |
| | vc 到队首但 b≤0 → **吃 0** | −100 | 100 |
| T3 200@9.98 | #103 要 200,预算已空 | −300 | **+200** |

守恒:虚拟 800 + 反事实真实 700(#101 的 500 + #102 的 200)= **1500 = Q** ✓
位移 300 = 磁带真实成交 1000 − 反事实真实成交 700 ✓

→ `va=400 vb=400 vc=0`,`displaced=300`

## 案例 2:同时刻 marketable 共享深度 + 扫价穿透 + 零位移(吃 slack)

盘口:买 `10.00×300(#101)`;卖 `10.02×200(#201)` `10.03×300(#202)`
主动卖单 `#301` 限价 10.00,**Q=600**;真实买盘只有 300 → 磁带只成交 300(**slack=300**)

虚拟腿(同 t0):`wa` 买@10.03×400 | `wb` 买@10.03×400 | `wc` 买@10.00×200

**t0 跨价**:`wa` 吃 200@10.02 + 200@10.03 → 满 400,均价 **10.025**,位移 +400
`wb` **只能吃 wa 剩下的**:10.02 已空 → 10.03 只剩 100 → 吃 100,残量 300 挂 10.03,位移 +100(累计 **500**)

**扫单**:`wb` 挂在 10.03,**价格优于真实买一 10.00** → #301 **先打 wb**:
- wb 被扫穿成交 **300**(成交价 = 我的限价 10.03)→ b: 600 → 300
- #101 要 300,预算正好够 → b=0,**真实单一股没少拿 → 本次扫单零位移**
- wc 到队首但 b=0 → 吃 0

wb 吃的 300 正是 #301 的 **slack** ✓

→ `wa=400(avg 10.025)`,`wb=400(avg 10.03, through=300)`,`wc=0`,`displaced=500`(全部来自 marketable)

## 案例 3:前方撤单 + 同毫秒上下界 + 策略撤单

盘口:买 `10.00` = `#101×500` + `#102×300` = **800**;卖 `10.05×1000`
**09:36:00.000 同一毫秒**(磁带序):`撤 #101(500)` → `主动卖单 #301 到达(Q=1000)` → `成交 300@10.00(吃 #102)`

虚拟腿:`x1` 买@10.00×400 | `x2` 买@10.00×200(09:35:30 策略撤单)

`x2` → 下一个事件即置 **CANCELLED**,成交 0,**不占预算**

`x1` 三种口径:
- **中性**(磁带序:先撤后成交):撤 #101 → 前方 800→300;成交 300 吃光前方 → 到队首;b=1000−300=700 → **吃满 400**
- **乐观**(先撤后成交)= 磁带序 → **400**
- **悲观**(先成交后撤):成交先到时前方仍是 **800**,只扣 300 → 剩 500,**没到队首 → 0**;撤单后到已无用 → **0**

→ **区间展开 `[pess=0, 中性=400, opt=400]`**
位移:1000 − 300(真实) − 400(我) = 300,从未变负 → **0**(#301 还剩 300 挂住,真实 #102 拿满)

## 案例 5:Q 兜底(主动单无委托记录)+ 预算跨档转移 + PARTIAL→CANCELLED

#301 **无委托记录**(SH 41.2% 的立即全成主动单场景)→ Q=该单总成交量 500+300=**800**。
盘口:买 `10.00×500(#101)` `9.99×300(#102)`;虚拟 `pa`买@10.00×400(09:38 撤)、`pb`买@10.00×600。

T1 `500@10.00`:吃前方 500(b→300)→ **pa 只成 300(PARTIAL)**,b=0 → pb 颗粒无收。
T2 `300@9.99`:两腿 `strictlyBetter` 但 b=0 → 不成;真实 #102 要 300 → b=−300,**位移 300**
(= #102 被 pa 截胡的量:主动单本愿卖到 9.99,反事实里先被 10.00 的 pa 接走 300)。
09:38 策略撤单:**PARTIAL→CANCELLED,已成 300 保留**。

## 案例 6:spread 内改善腿 + through 价=我的限价 + modify(cancel-replace)

盘口:买 `10.00×300(#101)`,卖 `10.05×1000`。`qa`买@**10.02**(spread 空档,ahead=0);
`qb`买@10.00,09:35:30 **modify→10.02×300**:qb 记 CANCELLED(ahead_rem 冻结 **300**),
新腿 `qb#2` 丢优先级排 qa 之后。卖主动 #301 限 10.00 挂 600(**Q=600**),磁带成交 300@10.00。

分配:qa、qb#2 都 `strictlyBetterThan(10.00)` → **through 成交,价=各自限价 10.02(非磁带价 10.00)**:
qa 满 200(b→400)→ qb#2 满 300(b→100);真实 #101 要 300 只剩 100 → **displaced=200**。
守恒:200+300+100=600 ✓ 经济合理性:#301 限价 10.00,卖 10.02 给虚拟腿只会更愿意。

→ `qa=200@10.02(through)`,`qb=0 CANCELLED(ahead_rem 300)`,`qb#2=300@10.02(through)`,`displaced=200`

## 案例 7:前方"先被吃一部分、再撤剩余"(双扣探针)+ PARTIAL 终态

## 案例 8:开盘竞价边际成交 + 插队位移(曾暴露 2 个 bug)

竞价累积:买 `10.00×400(#101)`、`9.98×300(#102,09:20:01 到)`;卖 `9.97×600(#201)` `9.98×100(#202)`。
p\* 推演:9.97→min(700,600)=600;**9.98→min(700,700)=700(平衡)**;10.00→400 ⇒ p\*=9.98,maxVol=700。
虚拟 `xb`买@9.98×200,**t0=09:20:00.5(在 #102 之前!)** → ahead=0。

反事实:加入 xb 后 9.98 档需求 900 > 供给 700,按时间优先 xb 排 #102 前
→ **xb 成 200,#102 只拿到 100(被挤走 200)** ⇒ `xb=200@9.98`,**`displaced=200`**。

曾暴露:① OPT/PESS 把 09:25 竞价成交同毫秒缓冲到解叉之后 → uncross 无叉可撮,
上下界=0(已修:竞价段不缓冲,竞价撮合无"同毫秒次序"歧义);② 竞价成交从不入位移计(已修)。

## 案例 9:对手方过剩 → 吃过剩零位移(曾暴露边际公式低估 bug)

同案例 8 但 `#202` 挂 **300**:p\*=9.98,真实撮合 700(需求约束,**卖方过剩 200**,#202 只成 100)。
虚拟 `xc`买@9.98×200(09:21 到,#102 之后 → ahead=300):反事实需求 900=供给 900 → 全清,
**xc 成 200 且一股不挤**(吃的正是 #202 没人要的 200)⇒ `xc=200@9.98`,`displaced=0`。
`xd`买@9.90×100:低于 p\* → 竞价不成,转连续 RESTING。

曾暴露:旧公式 `min(marginalCleared−aheadQty, avail)` 用**真实边际清算量**封顶,
对手方过剩时把成交错判成 0(低估)。已修:`avail−aheadQty`(对手可成交量 − 排我前面的所有人),
并同步修正 aheadQty(前方边际单被撮掉部分)与位移(超出过剩量的部分才计)。

## 案例 11:竞价打印不双扣队列 + 转连续排队位置保留(曾暴露 2 个 bug)

竞价簿:买 `10.00×400(#101)` `9.98×600(#102)`;卖 `9.97×600` `9.98×300` ⇒ p\*=9.98,maxVol=900,
真实撮合:#102 只成 500(**需求过剩 100 留在前方**)。`za` 买@9.98×400(09:21 到,#102 之后)→ ahead=600。

- **uncross**:avail=900−400−… ⇒ za 吃 0;前方按边际结清量 500 消耗 → **ahead=100**(=#102 残量)✓
- **竞价打印(500@9.98)不得再扣**:曾暴露 uncross 已结清、打印又 `consumeAhead` → 100−500 被
  钳到 0(双扣;真实数据 000566 前方 18.88M→0.25M,收盘腿 ahead_remaining 恰差一个收盘竞价量)。
- **09:27(settle gap)新买单 #103×500 到达** → 排我**后面**。转连续 reset 曾直接取整档簿深
  600(把 #103 算到我前面,000566 实测 9.5M→21.7M,成交被推迟);已修:`min(簿深, 自身追踪值)`=**100**。

→ `za=150 PARTIAL,ahead_rem=0,displaced=150`(修复前:0 成交 RESTING,ahead 350——三重错误叠加)

## 案例 10:收盘竞价 uncross + 15:00 打印不得双吃(曾暴露 2 个 bug)

连续段无成交;14:58 穿叉卖单 `#301` 9.98×600 累积进簿(收盘竞价不撮合)。
`ya` 买@10.03×500(10:00 挂,ahead=0)存活到收盘 → PENDING_AUCTION。

15:00 uncross(注:tracker 在**第一笔打印之后**的簿上求 p\*;打印是"两侧等量对减"的
已撮对,`avail/marginalCleared/surplus` 对此**不变**,推演结果与完整叉簿一致):
p\*=9.99,`ya` 严格优于 p\* → 成 `min(500, avail=400)=400@9.99`,**PARTIAL**;
位移 = 400 − 卖方过剩 100 = **300**。

**双吃探针**:15:00 的两笔打印(200+300@9.99)是 uncross 已分配流动性的磁带记录,
**不得再经预算路径填充 ya 剩下的 100**。曾暴露:① 开盘侧有 settle-gap 门挡打印,
收盘侧没有 → ya 被打印再喂 100 → 500/FILLED(双重计入;旧代码靠"uncross 不清
aheadQty"碰巧挡住,ahead=0 的腿照样双吃)。已修:`closeUncrossed_` 计入
`inAuctionPhase()`。② 竞价部分成交后状态硬置 RESTING,与连续段 fillMe 的
PARTIAL 口径不一致(真实数据里所有过收盘的部分成交腿都误报 RESTING)。已修。
